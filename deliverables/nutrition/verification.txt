Beaches calorie estimates — local verification, October 26, 2026

Story: a reader opens a menu, drink list or dish search and sees a calorie
scenario with its serving basis, evidence grade, component assumptions and sources.
The static page embeds the same dataset used by the downloadable audit and report.

Coverage: 533 existing menu rows; 480 modeled, 53 unavailable. Restaurant views
contain 505 rows (470 modeled, 35 unavailable); Bars & drinks has 28 (10 modeled,
18 unavailable). Duplicate lunch/dinner entries remain separate menu records.
Unitemized buffet signs have an unavailable notice, not an assumed buffet total.

Passed:
- 10 Python domain checks, including independent component-sum replay for every
  numeric row, withheld values, ID integrity, whole-pizza/four-piece-roll serving
  bases, shared-steak arithmetic, cocktail conflicts and optional-side exclusions.
- Generated profile/data/report/embedded-page bytes match a clean rebuild.
- Browser at 320 px light, 390 px dark and 1440 px light: menu and tab display,
  assumption expansion, matching USDA links, dish search, drink list, unavailable
  explanations, searchable standalone report and local-resource responses.
- Zero JavaScript page errors, zero failed local-resource status codes, and no
  page horizontal overflow on the menu views checked.
- Visual review of 320 px steak detail, 1440 px pizza search, 390 px dark cocktail
  unavailable state and 1440 px report. Serving labels, ranges and source details
  fit the checked views without clipping or overlap.
- git diff --check and service-worker JavaScript syntax.
- October 26 photo release checks: 88 browser-decoded catalog files at mobile
  and desktop widths, 26 galleries, 15 rendered matched dish-photo elements;
  enlarged viewer with historical/extra-side notes and publisher credits.
  All 47 new photos were reviewed on contact sheets; the four newly matched
  dish images were additionally reviewed full size. Mobile viewer and desktop
  French-onion-soup search were visually inspected after integration.

Flow boundaries: static HTTP page -> embedded reviewed dataset -> item identity
lookup -> calorie/serving HTML. No backend, authentication or external API is
required for calculations. The offline navigation cache remains network-first;
the calorie data is embedded in that same HTML. Live HTTPS service-worker offline
behavior was not exercised on the local HTTP preview.

Limitations: software consistency is verified; actual food weight, composition,
calories and current availability are not. All numeric estimates remain Grade D.
This is not a comprehensive menu refresh or official Beaches nutrition disclosure.

Publication: this report records the local preflight before release. The user
approved publishing the estimates and additional photos on October 26, 2026.
Production state must be established separately by deployment and live checks.
